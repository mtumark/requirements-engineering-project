# Week 7 - Wireframes

## 1. ACTOR AND GOAL

Actor: Student

Goal: The student wants to check a equipment and make a booking for a selected date and time.


## 2. WHY THIS JOURNEY MATTERS

The project involves booking management. A simple self-service booking journey could help student check availability and submit booking more clearly.

The prototype will focus on one important user journey rather than trying to show every function in the system.


## 3. PROPOSED PROTOTYPE SCREENS

SCREEN 1: BROWSE EQUIPMENTS

Purpose:
Allow the user to browse the equipments that can be booked.

Possible content:
- Equipment name or type.
- A "View Availability" button.

Open question:
- What equipment information should be displayed to help users choose?
- What if the equipment is out of stock or what if the equipment is not available?


SCREEN 2: View Equipment Details

Purpose:
Allow the user to check the availability of a selected equipmebt. 

Possible content:
- Selected equipmebnt.
- *Date available.
- *Stock available.

Open questions:
- How should availability be displayed?
- How frequently is availability updated?
- Will it show stock, availability?
- What will happen if the equipment is out of stock?


SCREEN 3: CHOOSE DATE AND TIME

Purpose:
Allow the user to select the intended booking date and time.

Possible content:
- Selected equipment.
- Booking date.

Open questions:
- Are there minimum or maximum booking durations?
- How far in advance can users book?
- What should happen if another user has already booked the selected time?


SCREEN 4: BOOKING VALIDATION

Purpose:
Validate student selected date and time.

Possible content:
- Error messages.

Open question:
- Do student need to select both time to proceed?


SCREEN 5: AFTER SUBMISSION

Purpose:
Show the user what happened after submitting the booking.

## 4. OPEN QUESTIONS

The following questions need clarification before the prototype can be treated as a complete representation of the requirements.

1. What equipment information should be displayed to help users choose?
2. What if the equipment is out of stock or what if the equipment is not available?
3. How should availability be displayed?
4. How frequently is availability updated?
5. Will it show stock, availability?
6. What will happen if the equipment is out of stock?
7. Are there minimum or maximum booking durations?
8. How far in advance can users book?
9. What should happen if another user has already booked the selected time?
10. Do student need to select both time to proceed?


The prototype should contain approximately four to six connected screens. Basic shapes and text are sufficient. The screens do not need to function as a real booking system.

Each screen should be linked to the project requirements where supported. Details that have not been confirmed should be recorded as open questions rather than treated as agreed rules.
